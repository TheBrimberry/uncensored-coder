Questions

The ones worth asking first

What happens when the generated code is wrong?

You see it fail before you do. Each build runs typecheck, units, and an end-to-end pass; failures feed back into the planner up to three times, and anything still red blocks promotion while leaving the preview URL live so you can look at it. If you'd rather fix it yourself, open the diff, edit the hunk, and accept — Filament plans around your edit instead of overwriting it.

Can I take the code and leave?

Yes, on every plan including the free one. Push the full git history to your own GitHub remote and run it anywhere that runs Node and Postgres. There is no Filament runtime dependency in the generated app — the only thing you lose by leaving is the build loop.

Does it work on an existing codebase?

Connect a repo and Filament indexes the schema, routes, and conventions already there, then writes in that style. It opens branches and pull requests rather than committing to your default branch, so your existing review process stays in charge.

Where does my data live during a build?

Each build runs in a single-tenant sandbox that is destroyed when the build ends. Preview databases are branched copies with production values masked by default, and a secrets scan runs before any artifact leaves the sandbox.

How long does a first build take?

A full-stack app of the size in the console above lands in about 19 seconds, and a mobile or extension target in roughly half that. Longer briefs mostly spend their time in the intent round — the questions at the start are what keep the build from being fast and wrong.
